## 本轮补齐的基础

1. 容器 ResourceKey 增加 provider/namespace，环境适配器将本地 ID 映射为稳定 Agent 环境，操作/日志保留 incarnation 防误操作。旧 Apple 本机历史仍可读。镜像等其他资源的完整全局标识、能力矩阵和 Docker/Kubernetes workload 语义尚待扩展。
2. 桌面从 Submitting 进入持久化 Queued 后才受理；日志原子替换及目录同步，损坏时拒绝写入且保留证据。并发上限 4，同资源串行；排队期间请求会持久化，不等当前命令结束。
3. 崩溃恢复不自动重放排队/重启命令；运行中的启停可按实际同身份状态核对。UI 支持失败项重试，部分重启失败只在实际停止时重试 Start；不把 UnknownOutcome 当作普通失败自动重做。
4. Agent 采用独立 SQLite 请求日志，持久化受理前不 ACK，同 request ID/同请求返回既有记录，异文拒绝；包含 owner/device/Agent 审计身份。去重记录未设置静默清理，容量满时拒绝新写入。
5. Agent 与 Relay 共用所有者绑定；Native 接入当前 GPUI，WebCrypto/WASM 模块复用协议。Web 使用独立设备私钥和公开签名授权，不复制根私钥；Native 自动续期不清除吊销记录。
6. 公共 core / management / runtime、Apple 变更与采样、Node bridge/SDK 已落地。桌面启动、导航、详情、表单、任务和读写后台按职责拆分，Node 和 Agent 复用同一 Command 执行逻辑；具体边界见 [ARCHITECTURE.md](../docs/ARCHITECTURE.md)。

普通构建第一次认领必须验证独立签发的应用凭据；**App Attest 与正式签发服务尚未实现**。开发 fixture 只用于 loopback FakeProvider。具体实现、限制与命令见 [REMOTE-DEVELOPMENT.md](../docs/REMOTE-DEVELOPMENT.md)。
